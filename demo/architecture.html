Architecture

One journey, two automation styles

The two suites test the same behaviour with different tools. The useful part is the shared shape: readable scenario, orchestration layer, scoped pages/components, and small helpers.

Shared layers

ScenarioOwns the product term and reads as the journey.
Flow / appCoordinates pages and carries the selected product name between steps.
Pages / componentsOwn locators and user-visible behaviour for one route or UI area.
Helpers / APIKeep pure checks such as title matching, image state, URL parsing, and add-to-cart payload validation.

Robot Framework

Robot is the readable submission layer. Resource files own locators; Python helpers stay value-only.

robot/
  tests/
    btech_cart.robot
  resources/
    flows/
    pages/
    components/
    api/
    assertions/
  libraries/
    cart.py
    images.py
    search.py
  README.md

Why this split

  • Test files stay business-readable.
  • Locators are close to the UI area they describe.
  • Python is used only where code is clearer than table syntax.
  • Browser Library still produces the detailed keyword log.

Playwright TypeScript

Playwright is the code-first implementation. Fixtures provide isolation; page and component objects keep selectors scoped.

playwright/
  tests/
    btech-cart.spec.ts
  src/
    app/
    pages/
    components/
    api/
    support/
    fixtures/
  README.md

What it demonstrates

  • test.step makes the report read like the scenario.
  • Components receive a root locator and stay inside their subtree.
  • The add-to-cart request is checked at the network layer.
  • Trace and video are enabled only for demo/CI evidence mode.

CI and demo publishing

Each push to main starts a clean run.

Robot jobInstalls Python dependencies, initializes Chromium, runs Robot, and uploads the latest Robot results.
Playwright jobInstalls Node dependencies, typechecks, runs Playwright with demo trace/video mode, and uploads the latest report.
Publish jobDownloads the fresh artifacts, restores old runs.json, appends the new timing record, captures the preview image, and deploys GitHub Pages.
