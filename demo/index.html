The assignment

Five required steps. Both implementations cover all five against the real site — nothing is mocked.

Open the B.TECH website.

Search for iphone17.

Select the first result and assert it has an image.

Add it to the cart.

Navigate to the cart.

Two implementations

Robot Framework is the primary submission. Playwright TypeScript is a deliberate second opinion: the same journey in the idiom of a code-first framework.

Robot Framework

Primary · Browser Library (Playwright engine)

  • Every browser action is a Browser Library keyword, so all 90 steps appear in log.html.
  • Python is reserved for what reads badly as table syntax — and never touches a locator.
  • Locators live in the resource that owns the UI area.
robot/
  config.py            single settings module
  tests/               the scenario
  resources/
    flows/             journey vocabulary
    pages/             route behaviour
    components/        header, cart drawer
    api/               response matchers
    assertions/        image checks
  libraries/           value-only Python

Playwright TypeScript

Secondary · @playwright/test

  • Components take a root Locator, not the page, so each owns its own subtree.
  • Fixtures give every test a fresh context; isolation is framework-managed.
  • test.step blocks make the HTML report read as the journey.
playwright/
  playwright.config.ts
  tests/               the spec
  src/
    app/               BtechApp entry point
    pages/             route objects
    components/        header, card, drawer
    api/               response observers
    support/           image + name helpers
    fixtures/          btech fixture

Separation of concerns

Both implementations use the same four layers. The names differ; the boundaries do not.

TestReads as the business journey. Owns test data (iphone17) and nothing else.
Flow / AppOwns the order of the journey and the state carried between steps, such as the selected product name.
Pages & componentsOwn locators and the behaviour of one route or one UI area. Scoped to a root, so repeated elements cannot collide.
Helpers & API observersPure logic: text normalization, URL parsing, payload assertions, image state. Value in, assertion out — no locators.

Run it yourself

No application to deploy, no test data to seed, no credentials.

Robot Framework

cd robot
uv sync --frozen
uv run rfbrowser init chromium
uv run robot --outputdir results --xunit xunit.xml tests

Headed: add --variable HEADLESS:false

Playwright TypeScript

cd playwright
corepack enable
pnpm install --frozen-lockfile
pnpm exec playwright install chromium
pnpm test

Report: pnpm report · Headed: pnpm test:headed
